# Художники и каталог в 0.2.0-beta.4

## База художников

Откройте «База художников…» в меню «Все файлы / Художники» каталога или на вкладке «Общие» настроек. Отдельное окно базы хранит имена художников независимо от открытой папки и наличия файлов. Список показывает число связанных работ и файлов, поле поиска учитывает имена и псевдонимы.

1. Нажмите «Добавить», введите имя и сохраните. «Имя в файлах» можно оставить пустым — используется имя художника. Псевдонимы раскрываются отдельно; несколько написаний разделяются точкой с запятой, запятой или переносом строки.
2. Выбирайте сохранённое имя в поле «Художник» на вкладке «Пачка». Несколько соавторов разделяются `;`. Известные имена и псевдонимы сопоставляются с существующим художником без учёта регистра.
3. Чтобы изменить имя художника, выберите запись, измените имя или написание для файлов и нажмите «Сохранить». Если у него есть связанные файлы, откроется вкладка «Имена работ». «Проверить имена связанных файлов…» позволяет открыть её отдельно.
4. Проверьте столбцы «Сейчас», «Новое имя» и «Состояние». Файлы без существующего имени художника отмечены как неизменяемые: новое имя к ним не приписывается. Конфликт не позволяет применить весь список.
5. «Сохранить и переименовать» запрашивает подтверждение. После завершения имя художника и изменения файлов доступны для общего Undo в истории переименования. Отмена подтверждения оставляет запись и файлы прежними.

При переименовании рассматриваются все файлы, связанные с работами художника, включая соавторские работы и другие папки. В имени заменяется существующий отдельный фрагмент имени, написания для файлов или псевдонима художника. Номер работы, версия, остальное название, соавторы и расширение сохраняются. Отсутствующий фрагмент не добавляется. Конфликты с существующими файлами, занятый файл или устаревший предпросмотр отменяют операцию; чужие файлы не перезаписываются.

Для художника без файлов изменение имени также попадает в журнал и отменяется через Undo. Редактирование одних псевдонимов сохраняет запись без файлового переименования. Имя другого зарегистрированного художника, включая вариант регистра, использовать нельзя.

«Удалить из базы…» после подтверждения удаляет только запись художника и его связи с работами. Файлы, работы, версии и связи остальных соавторов сохраняются. Удаление записи не переименовывает оставшиеся файлы: имя в них может продолжить распознаваться каталогом как незарегистрированное имя.

При открытии базы прежней версии схема обновляется до 2. Перед изменением создаётся отдельная копия `collection-before-schema-2-*.sqlite3` рядом с `collection.sqlite3`. Журнал хранит исходную и новую запись художника вместе с путями файлов. Undo после перезапуска восстанавливает обе части. Незавершённая операция сначала восстанавливается через историю; до этого редактирование и удаление художников блокируются.

## Откуда берётся группа в каталоге

«Художники» группирует **по текущим именам файлов**, а база хранит назначенные данные и историю независимо от этих имён. Например:

| Текущее имя | Группа каталога |
| --- | --- |
| `Худ1_001_v01_Работа.png` | `Худ1` |
| `Artist & Coauthor_002_v03_Title.webm` | Оба художника при распознанных именах |
| `HVR49nIaEAAYmKp.jpg` после Undo | `Без художника`, если ни одно известное имя не содержится в названии |

Файл после Undo не теряет данные работы и версии. Поэтому число связанных файлов в базе художников может отличаться от числа карточек в его группе текущей папки. Возврат исходного имени убирает файл из группы только тогда, когда это имя больше не распознаётся как имя художника. «Все файлы» снимает фильтр и показывает весь текущий каталог.

Автоматическое распознавание не записывает догадки в базу. Помимо зарегистрированных имён и псевдонимов поддерживаются схемы `Artist_001_v01_Title`, `artist-123456-789012`, `[Artist] Title` и `Artist - Title`. Обычные имена снимков и случайные хеши не превращаются в художников лишь из-за цифр в конце.

## Прокрутка и Проводник

В левой панели полоса прокрутки вертикальная, в нижней ленте — горизонтальная. Она появляется при выходе содержимого за доступную область. Можно перетаскивать бегунок, нажимать стрелки и свободное место полосы; колесо продолжает работать.

Маленькая кнопка расположения в заголовке каталога открывает Проводник и выделяет текущий файл. Если есть выбранные чекбоксами файлы, выделяются они все. Для разных папок выполняется отдельное открытие и выделение; повторяющиеся пути объединяются. ПКМ по конкретной миниатюре сохраняет отдельную команду показа именно этого файла.

## Проверки

`collection-and-rename` проверяет добавление художников до назначения файлов, дубликаты имён Unicode, замену псевдонима в соавторской работе, сохранение исходных имён, конфликты целей и доступа, устаревший предпросмотр, изменение регистра, Undo после повторного открытия, восстановление журнала, операции без файлов, удаление связей и резервную копию перед миграцией. Эти сценарии выполняются на созданных тестом файлах и отдельной базе.

`collection-view` проверяет группировку по текущему имени после Undo и внешнего переименования. `explorer-selection-plan` проверяет план выделения для одной и нескольких папок, Unicode, UNC и повторов путей; он не открывает окна Проводника. `artist-registry-gui` проверяет отдельное нативное окно на изолированном рабочем столе Windows и пропускается с кодом 77, если такой рабочий стол создать нельзя.

```powershell
cmake -S . -B build -DVIEWERY_GUI_TESTS=ON -DVIEWERY_VERSION=0.2.0-beta.4
cmake --build build --config Release --parallel
ctest --test-dir build -C Release -R "collection-and-rename|collection-view|explorer-selection-plan|artist-registry-gui" --output-on-failure
```

План выделения тестируется без вызова Shell. При локальной проверке Windows 11 функция `revealInExplorer` также вызвана для двух созданных тестом файлов: Shell вернул `S_OK`, а `SelectedItems` настоящего Проводника содержал ровно оба пути и исключал третий файл. Тестовые окна затем закрыты. Сценарии нескольких папок и UNC проверяются планировщиком; для ручной проверки выберите файлы из разных папок и нажмите кнопку расположения.
